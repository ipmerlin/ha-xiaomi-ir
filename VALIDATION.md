# Проверка версии 0.2.3

Дата: 26 октября 2026 года. Целевая версия HA: 2026.10.4.

## Диагностика 0.2.3

Добавлены этапы check_empty_slot / start_learning / read_learning и безопасная
структура ответа в журнале xiaomi_ir.remote. Три новых теста проверяют структуру,
отсутствие содержимого строк и все три этапа отказа без перезаписи команды.
Форматы допустимых ответов и правила повторов не менялись.

## Исправление 0.2.2

Числовой результат 0 поддержан для miIO.ir_learn, как и для ir_play.
Успешный ответ запуска обучения с result: 0 зафиксирован в первичном отчёте
[python-miio #444](https://github.com/rytilahti/python-miio/issues/444).
False и 0.0 остаются ошибками, неизвестные ответы не считаются успехом.

Для ir_read поддержаны коды -5002/-5003 и legacy-код 0 исключительно с точными
сообщениями no code for this key / learn timeout. Пример legacy-ответа:
[отчёт устройства](https://community.openhab.org/t/xiaomi-mi-infrared-remote-control/37423/81).
Пустой слот не считается выученной командой: сохраняется только полученный код
с совпадающим номером слота и корректным Base64. Автоматических повторов нет.

## Проверки

- 54 изолированных теста, включая полный цикл обучения и сохранение библиотеки.
- 6 контрактных тестов с настоящими HA 2026.10.4 и python-miio 0.5.12 на Python 3.14.
  Для обучения подменена отправка miIO, выполняются настоящие read/learn и разбор
  ответов; запись Store перехвачена и проверена. Сетевая отправка IR не выполняется.
- Проверяются отклонение неизвестных статусов, отсутствие перезаписи при ошибке,
  сохранение полученной команды и отсутствие miIO.ir_play во время обучения.
- HACS, Hassfest, Ruff и упаковка проверяются перед публикацией.

Физическое обучение на пользовательском передатчике не проверено. Совпадение
выявленных несовместимостей с конкретным отказом пользователя требует проверки
после обновления. Токены, содержимое ответов и ИК-коды в журнал не добавлены.
